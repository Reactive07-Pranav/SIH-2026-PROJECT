# Deploy: backend on Render, frontend on Vercel

Total time: about 15 minutes. Do Render first: Vercel needs the Render URL.

```
Phone / laptop ──► Vercel (static PWA from FRONTEND/) ──HTTPS──► Render (FastAPI from BACKEND/) ──► Render Postgres
```

Everything is configured in the repo:

| File | What it does |
| --- | --- |
| `render.yaml` | Render Blueprint: web service `sih-evidence-api` + Postgres `sih-evidence-db` |
| `vercel.json` | Vercel: builds `FRONTEND` into `FRONTEND/dist`, SPA fallback to `index.html` |
| `FRONTEND/vite.config.ts` | Stops a Vercel build that has no `VITE_API_URL`, so a broken frontend never goes live |

---

## 1. Backend + database on Render

1. Sign in at https://dashboard.render.com with GitHub.
2. Open this link (or **New → Blueprint** and pick the repo):
   https://dashboard.render.com/blueprint/new?repo=https://github.com/Reactive07-Pranav/SIH-2026-PROJECT
3. Render reads `render.yaml` and lists two resources: **sih-evidence-api** (web service) and **sih-evidence-db** (Postgres). Give the Blueprint any name and click **Apply**.
4. Wait until the service shows **Live** (first build: 3 to 5 minutes).
5. Copy the service URL from the top of the service page, for example `https://sih-evidence-api.onrender.com`.
   If the name was taken, Render adds a suffix (`https://sih-evidence-api-xxxx.onrender.com`). Use the URL Render shows.
6. Check it in a browser: `https://<your-service>.onrender.com/api/health` must show

   ```json
   {"status":"ok","service":"drug-evidence-api","demo":true,"warnings":[]}
   ```

### Environment variables Render sets for you

| Name | Value | Notes |
| --- | --- | --- |
| `DATABASE_URL` | from `sih-evidence-db` | wired by the Blueprint |
| `JWT_SECRET` | generated by Render | random; never in the repo |
| `SEED_DEMO` | `1` | creates `OP001`/`test123`, `OP002`/`test123`, `admin`/`admin123` and 28 synthetic signed records. **Set to `0` for real use.** |
| `CORS_ORIGIN_REGEX` | `https://sih-2026-project[a-z0-9-]*\.vercel\.app` | lets every Vercel production and preview URL of a project named `sih-2026-project` call the API |
| `CORS_ORIGINS` | `http://localhost:5173` | extra exact origins, comma-separated (add a custom domain here) |
| `PYTHON_VERSION` | `3.12.8` | |

## 2. Frontend on Vercel

1. Sign in at https://vercel.com with GitHub → **Add New… → Project** → import `Reactive07-Pranav/SIH-2026-PROJECT`.
2. On the configure screen:
   - **Root Directory**: leave as `./` (the repo root). `vercel.json` handles the rest.
   - **Environment Variables**: add

     | Name | Value |
     | --- | --- |
     | `VITE_API_URL` | your Render URL from step 1.5, `https://…onrender.com`, no trailing slash |

3. Click **Deploy**. When it finishes, open the `https://sih-2026-project….vercel.app` URL.
4. Sign in with `admin` / `admin123` (the login page lists the demo accounts when the API is seeded). The dashboard shows the demo records on the map.

If you named the Vercel project something other than `sih-2026-project`, edit `CORS_ORIGIN_REGEX` in Render
(Service → Environment) to match your Vercel domain, for example `https://my-name[a-z0-9-]*\.vercel\.app`, and save.

## 3. Before the demo

- **Wake the API.** A free Render service sleeps after about 15 minutes idle; the first request then takes up to a minute. Open `/api/health` a minute before you present.
- **Phone capture needs HTTPS:** the Vercel URL is HTTPS, so camera and GPS work on a phone.
- **Print the colour card:** `https://<your-vercel-app>/reference-card.svg` at 100% scale (105 × 75 mm).
- **Map tiles** come from OpenStreetMap over the internet; with no venue internet the map is blank (records and the table still work).
- **Free Postgres on Render expires after 30 days.** Upgrade the database or recreate the Blueprint after that.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Vercel build fails: `VITE_API_URL is not set` | the env var is missing | add `VITE_API_URL` in Vercel → Settings → Environment Variables, then **Redeploy** |
| Login page: *Network Error* / nothing happens | Render is asleep or still building | open `/api/health`, wait until it answers, retry |
| Browser console: *blocked by CORS policy* | Vercel domain doesn't match `CORS_ORIGIN_REGEX` | update the regex (or add the exact URL to `CORS_ORIGINS`) in Render |
| Changed `VITE_API_URL` but nothing changed | it is baked in at build time | Vercel → Deployments → **Redeploy** |
| `/api/health` shows a `JWT_SECRET` warning | the secret is empty | Render → Environment → set `JWT_SECRET` to a long random string |
| Everyone signed out after a Render redeploy | expected if `JWT_SECRET` changed | sign in again |
| Old UI still showing after a deploy | the PWA service worker is serving the cached app | reload twice, or close and reopen the tab |
